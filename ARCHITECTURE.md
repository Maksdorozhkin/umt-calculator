# Архитектура приложения Production Calculator

## Обзор

Flask-приложение для расчёта производственного выпуска на 7 станках с учётом простоев, сменного графика и справочника продукции. База данных — SQLite через Flask-SQLAlchemy. Поддержка PWA (Service Worker + Manifest).

---

## Модели базы данных

| Модель | Назначение |
|---|---|
| `Product` | Справочник продукции: название, количество кавитаций, циклов в минуту, штук в коробке, коробок в паллете |
| `MachineProduct` | Связь станка (1–7) с текущим продуктом (один продукт на станок) |
| `DowntimeLog` | Журнал простоев: станок, тип простоя, длительность (мин), время, заметка |
| `TapeCalculation` | История расчётов ленты: средний вес, % отходов, требуемое кол-во изделий, результат |

---

## Вспомогательные функции

### `get_current_shift() -> (shift_type, shift_end)`
Определяет текущую смену (**День** / **Ночь**) и время её окончания.

- Граница смены: **20:00**.
- Дневная смена: 08:00 → 20:00 того же дня.
- Ночная смена: 20:00 → 08:00 следующего дня (или 00:00–08:00 текущего).
- К времени конца смены применяется смещение **–10 минут** (`SHIFT_END_ADJUSTMENT`).

### `calculate_production(product, machine_id) -> (pallets, boxes, pieces)`
Рассчитывает ожидаемый выпуск до конца текущей смены для заданного станка.

1. Берёт оставшееся время до конца смены (мин).
2. Вычитает все зарегистрированные простои этого станка в пределах смены.
3. Считает штуки: `effective_time × cycles_per_minute × cavitations`.
4. Переводит штуки → коробки → паллеты, возвращает полные паллеты, оставшиеся коробки и штуки.

### Расчёт ленты (`/api/tape-calculation`)

| Метод | Путь | Функция | Описание |
|---|---|---|---|
| POST | `/api/tape-calculation` | `calculate_tape()` | Два режима расчёта: **прямой** (изделия → лента) и **обратный** (лента → изделия). |

#### Прямой расчёт (`required_pieces` в теле запроса)
1. Чистый вес партии: `(avg_weight × required_pieces) / 1000` кг.
2. Базовая потребность ленты: `pure_total / (1 – waste_percent/100)`.
3. Технологический коэффициент **× 1.05**.
4. Выход дробленки: `tape_needed – pure_total_weight_kg`.
5. Надбавка +10% поверх норматива: `tape_needed × 1.1`.

#### Обратный расчёт (`tape_available` в теле запроса)
1. Убирается техкоэффициент: `base_tape = tape_available / 1.05`.
2. Чистый вес: `base_tape × (1 – waste_percent/100)`.
3. Кол-во изделий: `int(pure_weight_kg × 1000 / avg_weight)`.
4. Дробленка при использовании всей ленты.

## Service Worker (`static/sw.js`)

Обеспечивает офлайн-работу PWA через кэширование и стратегии загрузки.

### Кэш-имена

| Константа | Значение | Назначение |
|---|---|---|
| `CACHE_NAME` | `"umt-v2.2"` | Динамический кэш (API-ответы) |
| `STATIC_CACHE` | `"umt-static-v2.2"` | Статические ассеты (JS, CSS, иконки, манифест) |

Версия инкрементируется при каждом изменении кода.

### Precache (`install`)

При установке SW открывает `STATIC_CACHE` и загружает список `PRECACHE_URLS`:
- `/`, `/static/js/app.js`, `/static/css/style.css`
- `/manifest.json`, иконки 192×192 и 512×512

`self.skipWaiting()` — принудительная активация нового SW без ожидания закрытия вкладок.

### Активация (`activate`)

- Удаляет все устаревшие кэши (имена не совпадающие с текущими `STATIC_CACHE` и `CACHE_NAME`).
- `self.clients.claim()` — немедленный перехват управления всеми открытыми вкладками.

### Стратегии fetch

| Тип запроса | Стратегия | Описание |
|---|---|---|
| `/api/*` (GET) | **Network-First** | Сначала сеть → при успехе копируем в `CACHE_NAME`. При сбое — кэш. Если и кэша нет — `{"offline": true}`. |
| Остальные GET | **Stale-While-Revalidate** | Мгновенно отдаём из `STATIC_CACHE`, параллельно обновляем с сервера. При следующем открытии — свежая версия. |
| POST / DELETE и др. | Прямой `fetch()` | Без кэширования (офлайн-очередь обрабатывается на клиенте в `app.js`). |

### Background sync

Слушает событие `sync` с тегом `"sync-offline-requests"`. При получении рассылает сообщение `SYNC_OFFLINE_QUEUE` всем открытым окнам — клиентский код (`app.js`) ловит его и запускает `replayOfflineQueue()`.

## Клиентская логика (`static/js/app.js`)

Весь фронтенд — один файл `app.js`, ~1800 строк. Работает как SPA-подобное приложение с табами по станкам.

### Офлайн-режим (PWA + localStorage)

| Механизм | Описание |
|---|---|
| `customFetch()` | Обёртка над `fetch()`. GET — network-first через SW. POST/PUT/PATCH/DELETE при офлайн-ошибке ставятся в FIFO-очередь (`localStorage`) и возвращают `{success: true, offline: true}` для прозрачности UI. |
| `replayOfflineQueue()` | При восстановлении сети проигрывает очередь FIFO. Успешные запросы удаляются, неудачные остаются. После синхронизации перезагружает все кэши с сервера. |
| `_syncTimer` | Периодическая проверка очереди каждые 30 сек при наличии записей. Останавливается, когда очередь пуста. |
| Событие `online` / SW message | Мгновенная попытка синхронизации при появлении сети или сообщении от Service Worker (`SYNC_OFFLINE_QUEUE`). |

### localStorage-кэши

| Ключ | Содержимое |
|---|---|
| `umt_products_cache` | Справочник продуктов (массив) |
| `umt_machine_product_cache` | Маппинг станок → продукт (`{"1": {...}, "2": {...}}`) |
| `umt_downtime_cache` | Журналы простоев по станкам (`{"1": [...], "2": [...]}`) |
| `umt_offline_queue` | Очередь офлайн-запросов (FIFO) |
| `umt_balance_cache` | Факт выпуска по станкам в паллетах/коробках (`{"1": {"pallets": 3, "boxes": 12}, "3": {"pallets": 0, "boxes": 5}}`) — для блока «Баланс смены» |

Загрузка данных всегда **двухэтапная**: мгновенно из localStorage → затем попытка обновления с сервера.

### Определение смены и расчёт времени

| Функция | Описание |
|---|---|
| `updateShiftDisplay()` | Определяет дневную (08:00–20:00) / ночную смену, переключает тему (`data-theme`), обновляет иконку ☀️/🌙. Запускается при старте и каждую минуту. Также вызывает `calculateShiftBalance()` и `renderTimeline()` для всех станков. |
| `getShiftEndMinutes()` | Возвращает конец смены в минутах от полуночи (1200 / 1920 / 480). |
| `getRemainingMinutes()` | Оставшееся время до конца смены минус 10 минут (смещение). |
| `getRemainingShiftMinutes()` | Аналог для расчёта выпуска — считает через Date-объекты, дублирует серверную логику `get_current_shift()`. |
| `getElapsedShiftMinutes()` | Прошло времени с начала смены в минутах. Для дневной: от 08:00 текущего дня; для ночной (вечер): от 20:00 текущего дня; для ночной (утро): от 20:00 предыдущего дня. Используется в блоке «Баланс смены» и таймлайне. |

### Расчёт выпуска (клиентский)

| Функция | Описание |
|---|---|
| `calculateProduction(machineId)` | **Полностью офлайн**. Дублирует серверный `calculate_production()`: берёт оставшееся время, вычитает все простои за смену, считает `pieces = time × cycles × cavitations`, переводит в паллеты/коробки/штуки. |
| `updateShiftOutput(machineId)` | Выпуск за **всю** смену (710 мин): `SHIFT_MINUTES × cycles × cavitations` → паллеты + коробки. Обновляется при изменении полей формы. |
| `updateHourlyRate(machineId)` | Производительность в час: `cavitations × cycles × 60` → паллеты/коробки/штуки в час. |

#### Расхождения с серверной `calculate_production()`

Формула расчёта идентична, но есть незначительные отличия:

- **Точность времени**: сервер считает остаток в дробных минутах (`(shift_end − now).total_seconds() / 60`), клиент — в целых (`Math.floor(diffMs / 60000) − 10`). Клиентский результат может быть меньше на до 1 минуты.
- **Источник данных**: сервер берёт параметры продукта и простои из БД, клиент — из полей DOM-формы и DOM-лога простоев (парсинг `.downtime-duration`). При офлайне клиент работает с localStorage-кэшем, поэтому результат может расходиться с серверным при устаревших данных.
- **Ограничения**: клиент дополнительно проверяет `cavitations ≤ 0 || cycles ≤ 0` → 0 и ограничивает `remainingBoxes` через `Math.max(0, …)` (на сервере значение математически всегда ≥ 0).

### Управление продуктами и станками

- **Автокомплит** — поиск по справочнику продуктов при вводе названия (для каждого из 7 станков).
- `fillProductData()` — автозаполнение полей формы при выборе продукта.
- `saveProduct()` — сохранение/обновление продукта + привязка к станку. При офлайн — запись в localStorage-кэш.
- `loadMachineProduct()` — загрузка текущего продукта станка (сервер → fallback на localStorage).

### Баланс смены (Shift Balance)

Компактный блок внизу панели каждой машины — показывает расхождение между фактом выпуска и планом.

#### HTML-структура (в `templates/index.html`)

Каждая машина получает блок `#shiftBalance{machineId}` с полями:
- `#factPallets{machineId}` / `#factBoxes{machineId}` — ввод факта выпуска в паллетах и коробках
- `#elapsedTime{machineId}` — прошло времени с начала смены
- `#expectedOutput{machineId}` — должно быть по расчёту (паллеты + коробки)
- `#outputDiff{machineId}` — разница в паллетах/коробках (факт − расчёт, округление до целой коробки вниз)
- `#unaccountedDowntime{machineId}` ≈ неучтённый простой в минутах
- `#progressBar{machineId}` / `#progressText{machineId}` — прогресс-бар с процентом

#### Логика расчёта (`calculateShiftBalance(machineId)`)

1. **Прошло времени** = текущее время − начало смены (08:00 или 20:00) → минуты.
2. **Должно быть** = `(прошло_времени − записанные_простои) × такты/мин × кавитации` → штуки → паллеты + коробки (`Math.floor` до целой коробки).
3. **Факт выпуска** = `паллеты × коробок_на_паллете × штук_в_коробке + коробки × штук_в_коробке` → штуки (для внутренних расчётов).
4. **Разница** = `факт − должно_быть` → вывод в паллетах/коробках с округлением вниз до целой коробки.
5. **≈ Неучтённый простой** = `abs(разница) / (такты × кавитации)` → минуты (только если разница < 0).
6. **Прогресс** = `(факт / должно_быть) × 100` %.

#### Цветовая индикация

| Состояние | CSS-класс | Условие |
|---|---|---|
| 🟢 Данные сходятся | `status-ok` | `abs(разница) ≤ 5% от расчёта` |
| 🔴 Забыл указать простой | `status-danger` | `факт < расчёт − 5%` (показывает строку «≈ Неучтённый простой») |
| 🟡 Впереди графика | `status-warning` | `факт > расчёт + 5%` |

#### Кэширование факта выпуска (`umt_balance_cache`)

- Ключ: `machine_id` → объект `{ pallets, boxes }` (паллеты и коробки).
- Сохраняется при каждом изменении любого из двух полей ввода.
- Восстанавливается из localStorage при загрузке страницы.
- Полностью клиентское — не требует сервера.

#### Обновление

Вызывается:
- При вводе факта выпуска (`input` event)
- При добавлении/удалении простоя (автоматически)
- Каждую минуту через `updateShiftDisplay()`

### Таймлайн смены (Timeline)

Визуальная шкала времени смены с сегментами «Работа» и «Простой».

#### HTML-структура

Каждая машина получает:
- `#timelineContainer{machineId}` — контейнер таймлайна
  - `#timelineBar{machineId}` — горизонтальная полоса с цветными сегментами
  - `#timelineLabels{machineId}` — подписи под сегментами

#### Логика рендера (`renderTimeline(machineId)`)

1. Парсит записи из лога простыхв (`.downtime-entry` в DOM) — извлекает время начала и длительность.
2. Сортирует по времени начала, пропускает будущие простои.
3. Строит чередующиеся сегменты: `Работа → Простой → Работа → ...`
4. Ширина сегмента пропорциональна длительности (`flex` CSS).
5. Цвет простоя зависит от типа (через CSS-классы `color-*`).

#### Цвета сегментов

| Тип | CSS-класс | Цвет |
|---|---|---|
| Работа | `timeline-work` | зелёный (`var(--success)`) |
| Ролик | `color-roller` | оранжевый (`#f4a261`) |
| Брак ленты | `color-scrap` | красно-оранж (`#e76f51`) |
| Поломка | `color-breakdown` | красный (`#e63946`) |
| Настройка | `color-setup` | синий (`#457b9d`) |

Лог простыхв свёрнут по умолчанию (`.collapsed`). Кнопка «⏱ Простои ▾» переключает видимость через CSS-класс. Экономит место на экране — таймлайн даёт быстрый обзор, лог — детали.

#### Обновление

Вызывается:
- При добавлении/удалении простоя (автоматически)
- Каждую минуту через `updateShiftDisplay()`

### Калькулятор ленты

- **Прямой расчёт**: изделия → лента (через сервер `/api/tape-calculation`).
- **Обратный расчёт**: доступная лента → изделия.
- **Вес рулона** (`calculateRollWeight()`) — полностью клиентский, без запросов к серверу:
  - ПП обычная шпуля (D=18 см): `((t×2+18)² − 324) × w / 1413`
  - ПП железная шпуля (D=16 см): `((t×2+16)² − 256) × w / 1413`
  - ПЭТ шпуля (D=17 см): `π × ((t+8.5)² − 72.25) × w × 0.00131`

### Калькулятор изделий (`setupItemsCalculator`)

Считает ±5% от заказа, конвертирует штуки в паллеты/коробки. Поддерживает три режима:
- Остаток не введён — расчёт от всего заказа.
- Отрицательный остаток — `|remaining|` штук доделать.
- Положительный остаток — сверх плана.

| Pull-to-Refresh | Мобильный жест свайпа вниз → `window.location.reload()`. |
| Service Worker | Регистрация `/sw.js`, автопроверка обновлений каждые 5 мин, prompt при наличии новой версии. |
