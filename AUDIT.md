# 🔍 Аудит «Калькулятор производства» — Отчёт

## Стек
Flask + SQLAlchemy (SQLite) → Jinja2 шаблоны → Vanilla JS фронтенд с PWA/Service Worker и оффлайн-очередью.

---

## 🔴 КРИТИЧЕСКИЕ ОШИБКИ

| # | Файл | Проблема | Описание |
|---|------|----------|----------|
| 1 | `index.html` + `app.js` | **Двойная регистрация Service Worker** | SW регистрируется и в `<head>` (инлайн-скрипт), и внизу `app.js` (`navigator.serviceWorker.register('/sw.js')`). Дублирование вызывает лишние события `install`/`activate`. |
| 2 | `index.html` (строки ~380) | **Сломана HTML-структура вкладки «Калькулятор изделий»** | Блок `<div class="tab-content" id="items-calc">` содержит лишний закрывающий `</div>` и вложенность нарушена — `items-calc-results` оказывается вне своего контейнера. Это ломает CSS-стили и табы. |
| 3 | `app.js` — `customFetch()` | **Потенциальная бесконечная очередь оффлайн-запросов** | При длительном отсутствии сети каждый проваленный запрос попадает в `offlineQueue` (IndexedDB). Нет лимита размера очереди и механизма очистки старых записей — память браузера будет расти. |
| 4 | `app.py` | **Hardcoded `SECRET_KEY`** | Значение по умолчанию `'super-secret-key-change-me'` закомментировано, но если переменная окружения не задана — Flask упадёт или будет использовать пустой ключ. Нужно либо `os.environ.get()` с fallback на `secrets.token_hex()`, либо явная ошибка при запуске. |
| 5 | `app.py` — все API-маршруты | **Отсутствие CSRF-защиты** | POST/DELETE запросы (`/api/product/<id>`, `/api/downtime/<machine_id>` и др.) не проверяют CSRF-токены. Для внутреннего приложения риск ниже, но уязвимость остаётся. |
| 6 | `app.py` — все API-маршруты | **Нет аутентификации / авторизации** | Любой, кто имеет доступ к URL, может менять данные, удалять продукты и простои. Для производственного стенда это допустимо, но стоит задокументировать как known risk. |

## 🟡 ПРЕДУПРЕЖДЕНИЯ (важно исправить)

| # | Файл | Проблема |
|---|------|----------|
| 7 | `app.py` — `DowntimeLog` | **Простои не очищаются по смене даты.** Таблица `downtime_logs` растёт бесконечно. Нет scheduled job или тригера для архивации/очистки старых записей. |
| 8 | `app.py` — API маршруты | **Нет try/except на уровне view-функций.** Если SQLAlchemy выбросит `IntegrityError` (например, двойное сохранение), сервер ответит 500 без валидного JSON. Каждый маршрут нужно оборачивать в `try/except`. |
| 9 | `app.py` — валидация | **Нет валидации входных данных.** Поля `cavitations`, `cycles`, `pieces_per_box` принимаются как `float(request.json.get(...))` без проверки на `None`, отрицательные значения или `0`. Деление на ноль в расчётах приведёт к `ZeroDivisionError`. |
| 10 | `sw.js` | **SW не кеширует сам себя.** `/sw.js` явно исключён из `PRECACHE_URLS` (комментарий подтверждает). При первом запуске оффлайн SW может быть недоступен, и PWA перестанет работать. |
| 11 | `sw.js` — `sync` event | **Background Sync не делает реальной синхронизации.** Обработчик `sync` просто шлёт `postMessage` окнам — фактическую отправку оффлайн-очереди должен делать сам SW через `fetch`, а не делегировать клиенту. |
| 12 | `app.js` — `formatInputValue()` | **`parseInt('')` возвращает `NaN`.** Если пользователь очистит поле, `parseInt('')` → `NaN`, что сломает последующие расчёты. Нужна проверка `isNaN()`. |
| 13 | `index.html` — TODO-комментарий | **Блок «Отход / дроблёнка» не протестирован.** В шаблоне есть `<!-- TODO: Нужно протестировать... -->` рядом с `droblenkaCard`. Если расчёт не работает — блок нужно либо починить, либо удалить. |
| 14 | `requirements.txt` | **Pillow (PIL) в зависимостях, но не используется.** В коде нет импорта `PIL`/`Image`. Лишняя зависимость увеличивает поверхность атаки. |

## 🟢 ЗАМЕЧАНИЯ (best practice)

| # | Описание |
|---|----------|
| 15 | **SQLite для многопользовательского доступа.** SQLite имеет один writer на момент. Если 4+ машины пишут одновременно — будут `Database is locked` ошибки. Рассмотреть `check_same_thread=False` + `connect_timeout` или переход на PostgreSQL. |
| 16 | **Нет логирования.** Flask не настроен на файловое логирование. В продакшене ошибки теряются. Добавить `logging.FileHandler`. |
| 17 | **Нет health-check эндпоинта.** Для мониторинга/балансировки нужен `/health` или `/status`. |
| 18 | **Версии в `requirements.txt` не зафиксированы.** Только Flask пинится (`Flask==3.1.2`), остальные — плавающие. Запустить `pip freeze` для репроducible builds. |
| 19 | **Нет rate limiting на API.** `flask-limiter` или аналог защитит от случайных перегрузок. |
| 20 | **CSS-файл не проверялся.** `static/css/style.css` не был прочитан в этом аудите — потенциальные проблемы с responsive layout возможны. |

## 🎯 Приоритеты исправления

### Приоритет №1 — Ломает работу приложения
- Исправить двойную регистрацию SW (удалить дубликат из `index.html` или из `app.js`)
- Исправить сломанную HTML-структуру вкладки `items-calc`

### Приоритет №2 — Стабильность продакшена
- Добавить try/except на все API-маршруты
- Добавить валидацию входных данных (проверка на `None`, отрицательные значения, деление на ноль)

### Приоритет №3 — Надёжность и безопасность
- Ограничить размер оффлайн-очереди
- Зафиксировать зависимости через `pip freeze`
- Добавить логирование
